# Scripting guide

Gameplay in Lapis is written in C# classes that derive from `Behaviour` and are attached to entities
like any other component.

## Projects

Scripts live in a **project**: a folder with a `.lapis` file.

```
MyGame/
├─ MyGame.lapis          project file: name and start scene
├─ MyGame.csproj         generated by the editor for code completion (do not edit)
├─ Assets/
│  ├─ Scenes/            .lscene files
│  └─ Scripts/           .cs files (any folder under Assets works)
├─ Settings/
└─ .lapis/               cache (generated, ignored by git)
```

- **Project > New Project...** creates this layout with an empty scene and an example script.
- **Project > Open Project...** opens a folder or `.lapis` file. The editor reopens the last project on start.
- From the command line: `Lapis.Editor --project path/to/MyGame`.
- `samples/Sandbox` in this repository is a ready-made example project.

## Writing a script

**Project > Create Script...** creates `Assets/Scripts/<Name>.cs` and opens it in VS Code:

```csharp
using System;
using System.Collections.Generic;
using System.Linq;
using System.Numerics;
using Lapis;

/// <summary>Moves the entity with W A S D or the arrow keys.</summary>
public class PlayerController : Behaviour
{
    [Range(0, 20)]
    [Tooltip("Movement speed in units per second.")]
    public float speed = 5.0f;

    public override void Update()
    {
        float x = Input.GetAxis("Horizontal");
        float z = Input.GetAxis("Vertical");

        // -Z is forward in Lapis, so W (Vertical = +1) moves along -Z.
        Vector3 direction = Vector3.ClampLength(new Vector3(x, 0, -z), 1f);

        transform.Position += direction * speed * Time.DeltaTime;
    }
}
```

Inside a behaviour, `entity` is the entity it is attached to and `transform` is that entity's transform.

To attach a script to an entity, drag the `.cs` file from the Assets panel onto the entity in the Hierarchy, onto
the object in the Scene view, or onto **Add Component** in the Inspector — or pick it in **Add Component**. The class
must have the same name as the file (scripts created by the editor do).

## Libraries and `using` lines

Scripts are built against two things:

- **The engine library, `Lapis.dll`** (namespace `Lapis`): `Behaviour`, `Entity`, `Transform`, `Input`, `Time`,
  `Log`, `RigidBody`, `Physics`, `Camera`, `Light` and the rest of the engine. The editor copies it into
  `.lapis/Engine/Lapis.dll` (with `Lapis.xml`, the API descriptions) so VS Code can show completion and docs.
- **The .NET class library**: everything in the `System.*` namespaces, such as `Math`, `List<T>`, LINQ,
  `StringBuilder` or file access.

Every script the editor creates (Project > Create Script..., Create Script... in the Assets panel, and the example script of a
new project) starts with the same `using` lines, so it is clear where each type comes from:

| `using` | Gives you |
|---|---|
| `using System;` | Basic .NET types: `Math`, `Random`, `Exception`, `DateTime`... |
| `using System.Collections.Generic;` | `List<T>`, `Dictionary<TKey, TValue>`, `HashSet<T>`... |
| `using System.Linq;` | `Where`, `Select`, `OrderBy` and other queries on collections |
| `using System.Numerics;` | `Vector2`, `Vector3`, `Quaternion`, `Matrix4x4` |
| `using Lapis;` | The engine API |

The editor's compiler also adds these five namespaces to every script automatically, so a script without the
`using` lines (for example one written for an older version) still compiles. Other parts of .NET need their own
line, e.g. `using System.Text;` for `StringBuilder` or `using System.IO;` for files.

Libraries from NuGet are not supported yet: scripts can use `Lapis.dll` and the .NET class library only.

## Compiling and hot reload

The editor compiles every `.cs` file under `Assets` itself (no build step, no .NET SDK needed):

- when a project is opened, and
- automatically whenever a script file is saved.

After a successful compile the new code replaces the old one **without restarting the editor**. The open
scene keeps all its values: fields that already existed keep what you set in the Inspector, new fields get
their default value. The undo history is cleared at this point.

If a script has an error, the Console shows it with the file and line — double-click the message to jump
there in VS Code. The previous version of the scripts stays active until the error is fixed.

**Project > Recompile Scripts** forces a compile; **Project > Open in VS Code** opens the project folder.
For code completion in VS Code, install the C# extension; it uses the generated `.csproj`.

## Lifecycle

| Method | When |
|---|---|
| `Start()` | Once, before the first `Update` of the behaviour. |
| `Update()` | Every frame. Use `Time.DeltaTime` to make movement frame-rate independent. |
| `PhysicsUpdate()` | At a fixed rate (50 times per second by default), before each physics step. |
| `PostUpdate()` | Every frame, after all `Update` calls and physics — e.g. for cameras following a target. |
| `OnDestroy()` | When a started behaviour is removed, its entity is destroyed, or the game stops. |

The methods must be written exactly like this — `public override void Start()`. C# is case-sensitive, so
`start()` is a different method that the engine never calls; the Console shows a **LAPIS001** warning for such
methods (wrong letter case or a missing `override`) with the line to fix.

Disabled behaviours (`Enabled = false`) and behaviours on inactive entities receive no calls.
If a method throws an exception, the error is logged with its stack trace and that behaviour is disabled,
so one broken script does not stop the rest of the game.

> Scripts run in **Play mode**: press **Play** (Ctrl+P) in the menu bar. Keyboard and mouse input reach the game
> while the Game view has focus. The mouse cursor is then hidden and held in the window, so `Input.MouseDelta` and
> the `Mouse X` / `Mouse Y` axes keep working for a first-person camera however far the mouse moves. **Esc** gives
> the mouse back to the editor (the game keeps running); click the game picture in the Game view to continue playing.
> Everything changed while playing is discarded on **Stop**.

## Physics

Add a **collider** to give an entity a shape: `BoxCollider`, `SphereCollider`, `CapsuleCollider` or
`MeshCollider` (static objects only). Cubes, spheres and planes from the Create menu already have one.

| Setup | Behaves like |
|---|---|
| Collider only | A static obstacle: floors, walls. |
| Collider + `RigidBody` (Dynamic) | Falls, bounces and is pushed: crates, balls. |
| Collider + `RigidBody` (Kinematic) | Moved by your script through `transform`; pushes dynamic bodies but is never pushed back: moving platforms, a player you move directly. |
| Collider with **Is Trigger** | Detects other colliders passing through it without blocking them: pickups, checkpoints. |

Gravity and the physics rate are scene settings, edited in the **Scene Settings** tab next to the Inspector.
The Scene view draws collider outlines in green (blue for triggers); Edit > Show Colliders toggles them.

Moving a dynamic body:

```csharp
public class Jumper : Behaviour
{
    public float jumpSpeed = 6f;
    private RigidBody? _body;

    public override void Start() => _body = entity.GetComponent<RigidBody>();

    public override void Update()
    {
        // Only jump when standing on something: cast a short ray down from the centre.
        bool grounded = Physics.Raycast(transform.Position, -Vector3.UnitY, 0.6f);
        if (grounded && Input.GetKeyDown(KeyCode.Space))
        {
            _body!.Velocity = new Vector3(_body.Velocity.X, jumpSpeed, _body.Velocity.Z);
        }
    }

    public override void PhysicsUpdate()
    {
        float x = Input.GetAxis("Horizontal");
        float z = Input.GetAxis("Vertical");
        _body!.AddForce(new Vector3(x, 0, -z) * 20f);
    }
}
```

Collision events (on any behaviour of either entity):

| Method | When |
|---|---|
| `OnCollisionBegin(Collision collision)` | Two solid colliders start touching. `collision.Other`, `.OtherEntity`, `.Point`, `.Normal`. |
| `OnCollisionEnd(Collider other)` | They stop touching. |
| `OnTriggerBegin(Collider other)` | A collider enters a trigger (called on both entities). |
| `OnTriggerEnd(Collider other)` | It leaves the trigger. |

`RigidBody` API: `Velocity`, `AngularVelocity`, `AddForce`, `AddImpulse`, `AddTorque`, plus Inspector settings
for mass, damping, gravity, continuous collision and per-axis freezing.
`Physics.Raycast(origin, direction, out RaycastHit hit, maxDistance)` returns the closest hit
(`hit.Entity`, `hit.Point`, `hit.Normal`, `hit.Distance`); triggers are included.

Notes and current limits:

- Each entity uses one collider (extra ones are ignored with a warning). Build compound objects from child entities.
- Physics runs at a fixed rate (50 steps per second by default); transforms of dynamic bodies are updated each step.
- Changing a collider or rigid body in the Inspector while playing rebuilds that body.

| Field | Shown in the Inspector and saved? |
|---|---|
| `public float speed;` | yes |
| `[Serialize] private int _health;` | yes (shown as "Health") |
| `[DoNotSerialize] public int cache;` | no |
| `[HideInEditor] public int id;` | saved, but not shown |
| `public float Speed { get; set; }` | yes (public get and set) |
| `public float Double => speed * 2;` | no (read-only) |

Supported types: `float`, `double`, `int`, `bool`, `string`, enums, `Vector2`, `Vector3`, `Vector4`,
### Character Controller

A **Character Controller** (Add Component > Character Controller) moves a player or a creature without letting it
pass through walls:
- it slides along walls;
- it walks up stairs and slopes, and stays on the floor when walking down them;
- it falls with gravity;
- it pushes loose objects (dynamic bodies).

Its capsule stands on the entity's origin (the feet), drawn in green in the Scene view. Put the camera on a
child at eye height. It needs no Rigid Body and no other collider.

| Setting | Meaning |
|---|---|
| **Height**, **Radius** | Size of the capsule, in metres. **Center** is its middle; keep it at half the height so it stands on the origin. |
| **Step Height** | The highest step or kerb it walks up without jumping. |
| **Max Slope** | The steepest slope it walks up, in degrees; it slides down steeper ground. |
| **Use Gravity** | Falls on its own. Off: the vertical part of `Move` moves it up and down (flying, ladders). |
| **Mass** | How hard it pushes loose objects. |

Scripts call `Move` every frame with how far to go. Gravity, steps and walls are handled for them:

```csharp
using System;
using System.Numerics;
using Lapis;

public class FirstPersonPlayer : Behaviour
{
    public float speed = 4f;
    public float runSpeed = 7f;
    public float mouseSensitivity = 0.15f;
    public float jumpHeight = 1f;

    private CharacterController _controller = null!;
    private Transform _camera = null!;
    private float _yaw;
    private float _pitch;

    public override void Start()
    {
        _controller = entity.GetComponent<CharacterController>()!;
        _camera = transform.Children[0]; // the camera, a child at eye height (e.g. 1.6)
    }

    public override void Update()
    {
        // Look around: turn the body left and right, tilt the camera up and down.
        _yaw -= Input.GetAxis("Mouse X") * mouseSensitivity;
        _pitch = Math.Clamp(_pitch - Input.GetAxis("Mouse Y") * mouseSensitivity, -85f, 85f);
        transform.Rotation = MathUtil.FromEulerDegrees(new Vector3(0, _yaw, 0));
        _camera.LocalRotation = MathUtil.FromEulerDegrees(new Vector3(_pitch, 0, 0));

        // Walk where the body faces; Shift runs.
        var input = new Vector3(Input.GetAxis("Horizontal"), 0, -Input.GetAxis("Vertical"));
        var direction = Vector3.Transform(Vector3.ClampLength(input, 1f), transform.Rotation);
        var currentSpeed = Input.GetKey(KeyCode.LeftShift) ? runSpeed : speed;
        _controller.Move(direction * currentSpeed * Time.DeltaTime);

        if (Input.GetKeyDown(KeyCode.Space))
        {
            _controller.Jump(jumpHeight);
        }
    }
}
```

| API | What it does |
|---|---|
| `controller.Move(motion)` | Moves by `motion` metres this frame (`direction * speed * Time.DeltaTime`), stopping at walls |
| `controller.Jump(height)` | Jumps that many metres high when on the ground; returns whether it jumped |
| `controller.IsGrounded` | Whether it stands on walkable ground |
| `controller.Velocity` | How fast it actually moved (after walls and steps), in metres per second |
| `controller.Teleport(position)` | Puts it somewhere at once (its feet), e.g. a respawn point |

Triggers notice the character (`OnTriggerBegin` on the trigger's scripts), so a trigger box can start an event
when the player walks in. `Physics.Raycast` hits it, so a creature can check whether it sees the player. The
character itself passes through triggers. The entity's scale does not change the capsule.

`Quaternion` (edited as angles), `Color`, `Entity` and any component type. Drag an entity from the
Hierarchy onto an `Entity` or component field to assign it.

Attributes for the Inspector:

- `[Range(min, max)]` — slider for numbers.
- `[Tooltip("text")]` — help text on hover.

## Lights, fog and fading

**Lights.** A `Light` is `Directional` (the sun), `Point` (a bulb shining everywhere) or `Spot` (a flashlight).
**Create > Spot Light** adds one pointing down. A spot light shines along the object's forward direction (−Z):
- `SpotAngle` is the width of its cone in degrees;
- `SpotSoftness` sets the edge, from 0 (sharp) to 1 (fading from the centre);
- `Range` is how far it reaches.

The Scene view draws the cone of a selected spot light. Up to 8 point and spot lights light the scene together.
Only the directional light casts shadows for now.

A flashlight is a spot light on a child of the camera; turning it off is one line:

```csharp
public class Flashlight : Behaviour
{
    public override void Update()
    {
        if (Input.GetKeyDown(KeyCode.F))
        {
            var light = entity.GetComponent<Light>()!;
            light.Intensity = light.Intensity > 0f ? 0f : 6f;
        }
    }
}
```

**Fog** is a scene setting: tick **Fog** in the **Scene Settings** tab and its options appear:
- **Mode:** *Exponential* thickens smoothly with distance; *Linear* is clear up to a distance and then thickens
  evenly.
- **Color:** what the thickest fog looks like.
- **Density** (Exponential only): at 1 / density metres about two thirds of the view is fog.
- **Fog Start** and **Fog End** (Linear only): clear up to Start, only fog from End, in metres.
- **Fog Height:** the top of the fog, as a world height in metres. Objects below it are fogged and above it clear,
  like mist lying on the ground (e.g. 0.5). It also sets how far up the sky the fog reaches: from a camera inside
  the fog, a higher top covers more of the sky, and the highest value (50) hides it with the default density. A camera above
  the fog sees a clear sky.

The editor only shows the options that apply to the chosen mode, and the same goes for lights: **Range** only
for point and spot lights, the cone only for spot lights, **Cast Shadows** only for the directional light.

When the sky is off, fog seen from inside it also covers the empty background. Scripts can change the fog
while the game runs, for example to thicken it near a monster:

```csharp
var environment = entity.Scene.Environment;
environment.Fog = true;
environment.FogDensity = MathUtil.Lerp(0.05f, 0.3f, closeness);
```

**Fading** covers the game picture (the Game view and exported games, not the Scene view) with a colour:
- `Screen.FadeTo(color, seconds)` blends towards `color`, whose alpha says how much it covers;
- `Screen.FadeOut(seconds)` goes to black;
- `Screen.FadeIn(seconds)` clears the picture again;
- `Screen.IsFading` is true while a fade runs, and `Screen.FadeColor` is the colour shown now.

Fades follow game time, so they stop while the game is paused, and every Play starts with a clear picture.
A blink:

```csharp
public class Blink : Behaviour
{
    private bool _closing;

    public override void Update()
    {
        if (Input.GetKeyDown(KeyCode.Space) && !Screen.IsFading)
        {
            Screen.FadeTo(Color.Black, 0.08f); // eyes close
            _closing = true;
        }
        else if (_closing && !Screen.IsFading)
        {
            Screen.FadeIn(0.12f); // and open again
            _closing = false;
        }
    }
}
```

## Sound

Put `.wav` or `.ogg` files in `Assets` (for example `Assets/Sounds`). To play one from an object, drag the
sound from the Assets panel onto the object in the Scene view or the Hierarchy. This adds an **Audio Source**
with that clip, or changes the clip of the one it has. Its settings:

| Setting | Meaning |
|---|---|
| **Clip** | The sound. |
| **Volume**, **Pitch** | Loudness (1 = as recorded) and speed (2 = an octave higher). |
| **Loop** | Start over at the end: ambient noise, music, a humming machine. |
| **Play On Start** | Start as soon as the game starts (or the object becomes active). |
| **Spatial** | 3D sound: it comes from the object, louder on the side it is on. It is full volume within **Min Distance** and silent from **Max Distance** (metres). Turn it off for music and interface sounds, which are heard the same everywhere. |

You hear the game from the **Audio Listener** (Add Component > Audio Listener, usually on the player's camera)
or, without one, from the main camera. Sounds pause with the game and stop when it stops.

Scripts control sources and play one-off sounds. A sound in a script is a `string` field marked with
`[AssetReference(AssetType.Audio)]`; the Inspector then shows a slot to drop the sound into:

```csharp
using Lapis;
using Lapis.Assets;

public class Footsteps : Behaviour
{
    [AssetReference(AssetType.Audio)]
    public string step = "";

    public float interval = 0.5f;
    private float _timer;

    public override void Update()
    {
        var moving = Input.GetAxis("Horizontal") != 0 || Input.GetAxis("Vertical") != 0;
        _timer -= Time.DeltaTime;
        if (moving && _timer <= 0f)
        {
            AudioSource.PlayClipAtPoint(step, transform.Position, 0.7f);
            _timer = interval;
        }
    }
}
```

| API | What it does |
|---|---|
| `source.Play()`, `source.Play(otherClip)`, `source.Stop()`, `source.Pause()`, `source.UnPause()`, `source.IsPlaying` | Control an Audio Source; `Volume`, `Pitch` and `Loop` can change while it plays |
| `AudioSource.PlayClipAtPoint(clip, position, volume)` | A one-off 3D sound at a point (full within 1 m, silent from 30 m) |
| `AudioSource.PlayClip(clip, volume)` | A one-off sound heard the same everywhere |
| `AudioListener.Volume = 0.5f` | Overall volume of the game, e.g. for a setting in the menu |

A computer without a sound device runs the game silently. A sound file that is missing or cannot be read is
reported once in the Console.

## Tags

A tag is a short label such as `Player`, `Enemy` or `Pickup` that scripts use to find and recognise objects.
Every entity has exactly one tag; a new entity is `Untagged`.

**In the editor:** pick the tag in the **Tag** list under the name in the Inspector. **Add Tag...** at the bottom of
the list creates a new one; the project keeps its tags in the `.lapis` file (new projects start with `Player` and
`Enemy`), so the same list is offered for every scene. The **x** next to a tag in the list removes it from the
project after asking; objects in the open scene that use it become `Untagged` (Ctrl+Z gives the tag back to them).
Changing a tag can be undone with Ctrl+Z.

**In scripts** (inside a `Behaviour`, or on any component such as the `Collider` of a collision):

| Code | Result |
|---|---|
| `tag` | The tag of this script's entity, e.g. `"Player"` |
| `tag = "Enemy";` | Gives the entity a new tag (any text; it does not have to be in the project's list) |
| `CompareTag("Player")` | `true` when the entity has exactly this tag (case-sensitive) |
| `FindWithTag("Player")` | The first active entity with the tag, or `null` |
| `FindGameObjectsWithTag("Enemy")` | An array of every active entity with the tag (empty when there are none) |

The same members exist on `Entity` (`enemy.tag`, `enemy.CompareTag("Boss")`) and the searches on `Scene`
(`entity.Scene.FindWithTag("Player")`). Searches skip inactive entities and entities under an inactive parent.

```csharp
public class Turret : Behaviour
{
    private Entity? _player;

    public override void Start()
    {
        _player = FindWithTag("Player");
        tag = "Enemy";
    }

    public override void Update()
    {
        if (_player is not null)
        {
            transform.LookAt(_player.Transform.Position);
        }
    }

    public override void OnTriggerBegin(Collider other)
    {
        if (other.CompareTag("Player"))
        {
            Log.Info("The player is in range.");
        }
    }
}

public class Alarm : Behaviour
{
    public override void Start()
    {
        foreach (var enemy in FindGameObjectsWithTag("Enemy"))
        {
            enemy.IsActive = true; // wake every enemy
        }
    }
}
```

## Hierarchy folders

Folders in the Hierarchy organise the scene. They are **not** parents: an entity in a folder still has
`entity.Parent == null`, and a folder has no position, rotation or scale, so it never moves what is inside it.
Folders only hold top-level entities; the children of those entities come along with them, as usual.

Scripts can still use folders to find groups of objects:

```csharp
public class WaveStarter : Behaviour
{
    public override void Start()
    {
        // Every top-level entity in "Enemies" and in the folders inside it.
        foreach (var enemy in entity.Scene.FindEntitiesInFolder("Enemies"))
        {
            enemy.IsActive = true;
        }

        // A full path picks one folder when several have the same name.
        var bosses = entity.Scene.FindEntitiesInFolder("Level 1/Bosses", includeSubfolders: false);
    }

    public override void OnTriggerBegin(Collider other)
    {
        if (other.entity.IsInFolder("Pickups"))
        {
            Log.Info($"Picked up {other.entity.Name} from {other.entity.FolderPath}");
        }
    }
}
```

| API | Result |
|---|---|
| `entity.Folder` | The folder the entity is in (`SceneFolder`, with `Name`), or `null` at the top level or when the entity has a parent. |
| `entity.FolderPath` | Full path such as `"Level 1/Enemies"`, or `null`. |
| `entity.IsInFolder("Enemies")` | `true` when the entity is in that folder or in a folder inside it. Takes a name or a full path. |
| `scene.FindEntitiesInFolder("Enemies", includeSubfolders: true)` | Top-level entities in the folder(s) with that name, or the folder with that full path, in Hierarchy order. Set `includeSubfolders: false` to skip folders inside it. |

Folder names are case-sensitive. The parent of a child entity is always another entity — use `entity.Parent`
for that, and folders only for grouping.
