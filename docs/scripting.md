# Scripting guide

Gameplay in Lapis is written in C# classes that derive from `Behaviour` and are attached to entities
like any other component.

## Projects

Scripts live in a **project**: a folder with a `.lapis` file.

```
MyGame/
├─ MyGame.lapis          project file: name and start scene
├─ MyGame.csproj         generated by the editor for code completion (do not edit)
├─ Assets/
│  ├─ Scenes/            .lscene files
│  └─ Scripts/           .cs files (any folder under Assets works)
├─ Settings/
└─ .lapis/               cache (generated, ignored by git)
```

- **Project > New Project...** creates this layout with an empty scene and an example script.
- **Project > Open Project...** opens a folder or `.lapis` file. The editor reopens the last project on start.
- From the command line: `Lapis.Editor --project path/to/MyGame`.
- `samples/Sandbox` in this repository is a ready-made example project.

## Writing a script

**Project > Create Script...** creates `Assets/Scripts/<Name>.cs` and opens it in VS Code:

```csharp
/// <summary>Moves the entity with W A S D or the arrow keys.</summary>
public class PlayerController : Behaviour
{
    [Range(0, 20)]
    [Tooltip("Movement speed in units per second.")]
    public float speed = 5.0f;

    public override void Update()
    {
        float x = Input.GetAxis("Horizontal");
        float z = Input.GetAxis("Vertical");

        // -Z is forward in Lapis, so W (Vertical = +1) moves along -Z.
        Vector3 direction = Vector3.ClampLength(new Vector3(x, 0, -z), 1f);

        transform.Position += direction * speed * Time.DeltaTime;
    }
}
```

These namespaces are available in every script without `using`: `Lapis`, `System`,
`System.Collections.Generic`, `System.Linq`, `System.Numerics`.

Inside a behaviour, `entity` is the entity it is attached to and `transform` is that entity's transform.

## Compiling and hot reload

The editor compiles every `.cs` file under `Assets` itself (no build step, no .NET SDK needed):

- when a project is opened, and
- automatically whenever a script file is saved.

After a successful compile the new code replaces the old one **without restarting the editor**. The open
scene keeps all its values: fields that already existed keep what you set in the Inspector, new fields get
their default value. The undo history is cleared at this point.

If a script has an error, the Console shows it with the file and line — double-click the message to jump
there in VS Code. The previous version of the scripts stays active until the error is fixed.

**Project > Recompile Scripts** forces a compile; **Project > Open in VS Code** opens the project folder.
For code completion in VS Code, install the C# extension; it uses the generated `.csproj`.

## Lifecycle

| Method | When |
|---|---|
| `Start()` | Once, before the first `Update` of the behaviour. |
| `Update()` | Every frame. Use `Time.DeltaTime` to make movement frame-rate independent. |
| `PhysicsUpdate()` | At a fixed rate (50 times per second by default), before each physics step. |
| `PostUpdate()` | Every frame, after all `Update` calls and physics — e.g. for cameras following a target. |
| `OnDestroy()` | When a started behaviour is removed, its entity is destroyed, or the game stops. |

Disabled behaviours (`Enabled = false`) and behaviours on inactive entities receive no calls.
If a method throws an exception, the error is logged with its stack trace and that behaviour is disabled,
so one broken script does not stop the rest of the game.

> Scripts run in **Play mode**, which arrives with milestone M6.

## Fields in the Inspector

| Field | Shown in the Inspector and saved? |
|---|---|
| `public float speed;` | yes |
| `[Serialize] private int _health;` | yes (shown as "Health") |
| `[DoNotSerialize] public int cache;` | no |
| `[HideInEditor] public int id;` | saved, but not shown |
| `public float Speed { get; set; }` | yes (public get and set) |
| `public float Double => speed * 2;` | no (read-only) |

Supported types: `float`, `double`, `int`, `bool`, `string`, enums, `Vector2`, `Vector3`, `Vector4`,
`Quaternion` (edited as angles), `Color`, `Entity` and any component type. Drag an entity from the
Hierarchy onto an `Entity` or component field to assign it.

Attributes for the Inspector:

- `[Range(min, max)]` — slider for numbers.
- `[Tooltip("text")]` — help text on hover.

## Useful API

| API | Purpose |
|---|---|
| `transform.Position`, `.Rotation`, `.LocalScale`, `.Forward`, `.Right`, `.Up` | Position and orientation |
| `transform.LookAt(target)`, `transform.SetParent(other)` | Orientation and hierarchy |
| `entity.GetComponent<T>()`, `entity.AddComponent<T>()`, `entity.Destroy()` | Components and lifetime |
| `entity.Scene.Find<T>()`, `entity.Scene.FindByName("Player")` | Finding other objects |
| `Time.DeltaTime`, `Time.TimeSinceStart`, `Time.FrameCount` | Timing |
| `Input.GetAxis("Horizontal" / "Vertical" / "Mouse X" / "Mouse Y" / "Mouse ScrollWheel")` | Movement input |
| `Input.GetKey(KeyCode.Space)`, `GetKeyDown`, `GetKeyUp` | Keys |
| `Input.GetMouseButton(MouseButton.Left)`, `Input.MousePosition` | Mouse |
| `Log.Info("...")`, `Log.Warning`, `Log.Error` | Messages in the Console |
| `MathUtil.FromEulerDegrees`, `Vector3.ClampLength`, `MathUtil.Lerp` | Math helpers |
